Build Specification: Reasoning Lens for ChatGPT
Objective

Build a functional, interactive prototype called Reasoning Lens that looks and feels like ChatGPT.

The prototype helps users evaluate an AI-generated answer by highlighting specific parts that may require scrutiny. It should help users understand weaknesses in an answer without giving a generic trust score or replacing human judgment.

This is a controlled MVP/demo, so do NOT use an AI API. The AI response and Reasoning Lens analysis should be pre-configured in the application.

Tech Stack
Python
Streamlit
Custom CSS/HTML for the ChatGPT-like interface
No Gemini API
No external database required
User Flow

Open app → See pre-filled prompt → Click Send → See AI response → Reasoning Lens ON by default → Explore highlighted issues → Turn Lens OFF if desired

1. Initial Screen

Create a dark ChatGPT-style interface.

The screen should contain:

ChatGPT-like sidebar
Main conversation area
Bottom message input
A pre-filled prompt in the input box
Send button

Use this prompt:

“Our company needs to choose between three growth strategies. Strategy A has the highest projected ROI, Strategy B has the lowest implementation cost, and Strategy C has the strongest customer retention. Which strategy should we prioritize and why?”

The user should be able to click Send.

2. Pre-configured AI Response

When Send is clicked, display this response as if it was generated by ChatGPT:

Strategy A is the best option because it has the highest projected ROI. It offers the strongest financial return and therefore appears to be the most attractive growth strategy. While Strategy B has lower implementation costs and Strategy C has stronger customer retention, these advantages are less important than maximizing ROI. Therefore, the company should prioritize Strategy A.

Do not call an API. This response should be stored directly in the application.

3. Reasoning Lens

At the top of the AI response, display:

🔎 Reasoning Lens ON

The Lens should be ON by default.

Add a toggle so the user can turn it OFF.

When Reasoning Lens is ON

Highlight specific parts of the response.

Use different subtle colors for highlighted sections.

Highlight these sections:

Highlight 1

Text:

“Strategy A is the best option”

Issue type: Hidden assumption

Issue:

The recommendation assumes projected ROI should be the primary decision criterion.

Why it matters:

A strategy with higher ROI may still be worse if implementation costs, customer retention, or execution risk are significantly different.

Confidence:

Moderate

What to check:

Compare implementation costs, retention impact, and execution risk across all three strategies.

What could change the conclusion:

If Strategy C's retention advantage or Strategy B's lower implementation cost creates greater long-term value, the recommendation could change.

Highlight 2

Text:

“It offers the strongest financial return”

Issue type: Unsupported claim

Issue:

The response does not provide the underlying ROI estimates or explain how they were calculated.

Why it matters:

Without knowing the assumptions behind the projections, the strength of the financial advantage cannot be assessed.

Confidence:

Moderate

What to check:

Review the ROI calculations, assumptions, timeframe, and supporting data.

What could change the conclusion:

If the projected ROI depends on optimistic assumptions, another strategy could become more attractive.

Highlight 3

Text:

“these advantages are less important than maximizing ROI”

Issue type: Incomplete reasoning

Issue:

The response dismisses implementation cost and customer retention without comparing their actual business impact.

Why it matters:

Cost and retention can materially affect long-term profitability and growth.

Confidence:

High

What to check:

Compare the expected long-term value of ROI, implementation cost, and customer retention.

What could change the conclusion:

If retention or lower implementation costs produce greater long-term value, Strategy B or C could be preferable.

Highlight 4

Text:

“Therefore, the company should prioritize Strategy A.”

Issue type: Overconfident conclusion

Issue:

The recommendation is presented as definitive despite important information being missing.

Why it matters:

The best strategy cannot be determined from ROI alone.

Confidence:

High

What to check:

Assess the decision using multiple criteria and obtain the missing business data.

What could change the conclusion:

Different assumptions about costs, retention, execution risk, or time horizon could change the recommendation.

4. Interactive Issue Explanation

When the user clicks a highlighted section, show a clean Reasoning Lens panel/card.

The panel should contain:

Issue

Why it matters

Confidence

What to check

What could change the conclusion

Make the panel visually distinct but consistent with the ChatGPT dark theme.

Only one issue panel needs to be expanded at a time.

5. Reasoning Lens OFF

When the user switches:

Reasoning Lens ON → OFF

The application should:

Remove all colored highlights
Remove issue indicators
Hide the issue explanation panel
Display the exact same response as a normal ChatGPT response

When switched back ON, restore the highlights and interactive issue functionality.

6. Important Product Principles

Do NOT:

Show an overall trust score
Say the answer is definitely correct or incorrect
Automatically tell the user what decision to make
Claim that the Reasoning Lens is the ultimate authority
Rewrite the answer automatically
Use generic “AI confidence: 87%” indicators

The product should help the user evaluate the answer themselves.

The core question is:

“What parts of this answer should I pay attention to?”

Not:

“Can I trust this answer?”

7. Visual Design

Make the interface closely resemble modern ChatGPT:

Dark background
Left sidebar
Central conversation area
Rounded message/input containers
Clean typography
Minimal visual clutter
Responsive layout
Subtle orange/amber highlights for issues
Professional, polished appearance

The Reasoning Lens should feel like a native ChatGPT feature, not a separate application.

8. Prototype Requirements

The prototype must be fully functional without an API.

The following interactions must work:

User opens the app.
Pre-filled prompt is visible.
User clicks Send.
AI response appears.
Reasoning Lens is ON by default.
Highlighted sections are visible.
User clicks a highlight.
Relevant issue explanation appears.
User toggles Reasoning Lens OFF.
Highlights disappear and the response becomes clean.
User toggles it ON again.
Highlights and issue interactions return.

Keep the implementation simple and reliable. The goal is to demonstrate the Reasoning Lens product experience, not live AI generation.
